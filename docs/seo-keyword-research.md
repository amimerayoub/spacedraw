### D. Technical Multilingual SEO Review & Risk Mitigation

1. **URL Structure & `hreflang` Matrix:**
   * Subfolders `/en-us/`, `/en-gb/`, `/fr/`, `/es/`, `/de/`, `/ar/`, `/pt-br/`, `/ru/` are ideal because they consolidate domain authority on a single root domain.
   * **Correction on `hreflang` codes:**
     * Use regional codes `en-US` and `en-GB` (and optionally add a catch-all `en` pointing to `/en-us/` so English searchers in Canada, Australia, or India are covered).
     * Use language-only `fr`, `es`, `de`, `ar`, `ru` (and `pt-BR` + catch-all `pt` pointing to `/pt-br/`) so you rank across all French-, Spanish-, German-, Arabic-, Portuguese-, and Russian-speaking countries without needing 30 subfolders.
     * Set `x-default` to `/en-us/` (or the root `/` if `/` serves `en-US` or redirects cleanly).
     * Every page must include a **self-referencing `<link rel="canonical">`** and the full bi-directional set of `<link rel="alternate" hreflang="...">` tags for all 8 locales.
2. **Sitemaps:**
   * A **Sitemap Index (`sitemap-index.xml`)** referencing 8 per-locale sitemaps (`sitemap-en-us.xml`, `sitemap-ar.xml`, etc.), where each URL entry includes `<xhtml:link rel="alternate" hreflang="..." href="..." />` for all its translations, is the gold standard for crawling when there is no HTML language switcher.
3. **`lang`, `dir`, Open Graph, and Schema.org:**
   * Set `<html lang="ar" dir="rtl">` for Arabic and `dir="ltr"` for all others. Use CSS Logical Properties (`margin-inline-start`, `padding-inline-end`) so the glass UI flips automatically in RTL without separate stylesheets.
   * **Open Graph `og:locale`:** Must use underscores, not hyphens: `en_US`, `en_GB`, `fr_FR`, `es_ES`, `de_DE`, `ar_AR`, `pt_BR`, `ru_RU`.
   * **Structured Data:** Combine `["VideoGame", "WebApplication"]` (`applicationCategory: "GameApplication"`, `operatingSystem: "Any (Web Browser)"`, `offers: { "@type": "Offer", "price": "0", "priceCurrency": "USD" }`) with `FAQPage` schema for the 5 native FAQs on each home page.
4. **CRITICAL RISK ANALYSIS — "No Public Language Switcher":**
   * **SEO Risk 1 (Orphaned Locale Silos & Slow Discovery):** Googlebot primarily discovers and passes PageRank (link equity) between locales via internal `<a href>` links. `hreflang` tags and XML sitemaps help Google *discover* URLs, but they **do not pass internal link weight** the way standard `<a>` links do. If an English blog links to `/en-us/`, `/fr/` and `/ar/` get zero direct link equity unless linked in HTML.
   * **SEO Risk 2 (Wrong-Locale Landing):** A bilingual user travelling abroad or using an English OS might land on `/en-us/` and have no UI way to switch to `/de/`.
   * **How to Reduce These Risks Without a Header Switcher:**
     1. Ensure `sitemap-index.xml` is declared in `robots.txt` and submitted to Google Search Console and Bing Webmaster Tools (IndexNow).
     2. Put full `<link rel="alternate" hreflang="...">` tags in the `<head>` of **every** page so Google swaps the URL in SERPs based on the searcher's language.
     3. **Never auto-redirect users or bots based on IP or `Accept-Language` headers**—Googlebot crawls mostly from US IPs and will fail to index `/fr/`, `/ar/`, etc. if redirected.
